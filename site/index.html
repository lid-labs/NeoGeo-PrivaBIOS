Neo Geo MVS system ROM · v0.1 beta

A Neo Geo BIOS written from scratch, and tested game by game

Sprixe BIOS replaces the system ROM of a Neo Geo MVS board. Hold START + SELECT during a game and a menu opens with the game's settings, cheats, a memory editor and autofire remembered for each game. Operators get free play, no continue and a silent demo for every game, and one switch that turns cheats and debug off for the whole board. None of it comes from SNK's code or from UniBIOS.

Download

Get Sprixe BIOS v0.1

DraftThe files are not online yet. The download button will point to the first release.

One image, two byte orders. Pick the one your programmer or emulator expects.

sprixe-bios-v0.1.rom

MAME byte order, the same as the sp-s2.sp1 file in neogeo.zip. Burn it as is on most programmers.

sprixe-bios-v0.1-byteswapped.bin

Bytes swapped in pairs, for a programmer set the other way round. If the board shows nothing, try the other file.

On an MVS board

  1. Burn the image on a 27C1024 EPROM.
  2. Keep the original BIOS chip. Swap it out, mind the notch.
  3. Power on: the Sprixe BIOS screen shows for a moment, then the game starts.

In MAME

  1. Work on copies. Replace sp-s2.sp1 with the Sprixe BIOS file in neogeo.zip, and also in the game's zip if your set is non-merged: each of those zips carries its own copy of the BIOS, and MAME reads it first.
  2. Run the game with -bios euro.
  3. MAME warns WRONG CHECKSUMS for sp-s2.sp1. That warning means Sprixe BIOS is the BIOS in use.

Source code, issues and discussions: github.com/lid-labs/sprixe-bios.

How it's tested

Clean room, then a test for everything the player sees

A BIOS is the first code the board runs, and games keep calling into it for controls, credits and saves. Much of what it has to do is documented nowhere, so we measured it.

164games in the MAME catalogue, run under Sprixe BIOS, the SNK BIOS and UniBIOS 4.0
157test scenes, each judged on what the player sees or hears
201deliberate bugs, every one caught by its scene
14test images sent to a tester with a real MV-2F so far

Clean room

No code from SNK, UniBIOS or any game was copied or disassembled. The original BIOS was observed while it ran: under MAME (picture, sound, RAM, how often an address is read) and, early on, through bus traces in a co-simulation (addresses and timing). The code was written from what those observations showed and from public documentation.

This is slower. It also means Sprixe BIOS sometimes differs from the original on purpose, and each of those differences is written down with the reason.

Tests the player would notice

A scene plays a short sequence under MAME (a coin, START, a menu, a held button) and compares what is on screen and in the speakers against a reference run. Then we break the BIOS on purpose, one change at a time, and check that the scene fails. A scene that cannot fail is removed or rewritten.

The catalogue boots every game in the set and watches it play. Under Sprixe BIOS, 161 of 164 play. Two others freeze under the SNK BIOS and UniBIOS too, so the harness is the cause, and one (irrmaze) cannot be measured with a substituted BIOS.

MAME is not the hardware, and the real board keeps finding things it missed. The tester's MV-2F showed that Sprixe BIOS read the cartridge header at the wrong moment (fixed 24 October), that a consolized board without a TEST button could not reach the settings (25 October), and that a BlueRetro wireless adapter holds every button for a second when it wakes up (27 October). A shoot'em up played by hand on 28 October found the latest one: Alpha Mission II's ship drifted sideways. The fix is in testing below.

Thanks to Sebastian Klötzer, for testing every image on a real MV-2F board and reporting what MAME could not show.

Questions

Before you burn a chip

Will it run on my MV-1C, or on another MVS board?
We don't know yet. One real board has run Sprixe BIOS so far, a two-slot MV-2F. Under MAME it is also tested on the six-slot MV-6F. Other boards are untested. On some MVS boards the BIOS chip is soldered, and it needs a socket before you can swap it.
And on an AES console?
No. There is no Sprixe BIOS image for the AES console and none has been tried. What Sprixe BIOS has is an AES mode for an MVS board: set MODE to AES in the settings, and games show their home version, with PUSH START and their option menus.
Can I go back to UniBIOS or the SNK BIOS?
Yes: keep the chip you take out, and put it back the same way. Going the other way, Sprixe BIOS checks the soft-DIP blocks another BIOS left in backup RAM before a game reads them: a value out of range goes back to the cartridge default.
Can I try it without burning anything?
Yes, in MAME. Replace sp-s2.sp1 with the Sprixe BIOS file and run the game with -bios euro. The install steps give the details, including the non-merged sets.
Does autofire work in every game?
No, it depends on how the game reads the joystick. Measured under MAME on player 1's A button: 89 games see it fully, 25 partly, 35 never, and 15 were not measured. Last Resort, Alpha Mission II and the first Metal Slug see it. Pulstar, Metal Slug 2 and Metal Slug 5 see it partly. Blazing Star, Metal Slug 3, 4 and X read the joystick themselves, so no BIOS autofire reaches them.
My cabinet has no TEST button.
Turn board switch 1 ON, or hold START + SELECT at power-on: both open the settings screen. During a game, START + SELECT held about a third of a second opens the in-game menu. This came from the tester's consolized MV-2F.
Where are my scores and settings kept?
In the board's backup RAM: region, mode, cabinet settings, each game's soft-DIPs and autofire, and the high scores. Scores are not saved on the memory card.
What are the terms of use?
GPL-3.0-or-later. You can use it, burn it, share it and modify it; if you distribute a modified version, you share its source too. The code is our own, not derived from SNK or UniBIOS, and its source is on GitHub.
Manual

Using Sprixe BIOS

Controls are player 1's. A press counts once; hold a direction to repeat.

Power on
├── Boot screen ──────────── any button skips it
├── TEST held, START + SELECT held, or switch 1 ON
│   └── SOFT DIP SETTINGS
│       ├── REGION
│       ├── the cartridge's own settings
│       ├── CABINET SETTINGS ── FREE PLAY, NO CONTINUE, DEMO SOUND,
│       │                       CHEATS/DEBUG, DEBUG DIPS
│       ├── SCORE RESET
│       ├── MEMORY CARD ─────── saves, FORMAT CARD, copy with C
│       ├── MODE ────────────── MVS or AES
│       ├── HARDWARE TESTS ──── WORK RAM ... CROSSHATCH, CARTRIDGE CRC
│       ├── JUKEBOX
│       └── RESET TO DEFAULTS
└── The game
    ├── TEST or START + SELECT, held about 1/3 s in a game
    │   └── IN-GAME MENU
    │       ├── RESUME
    │       ├── RESTART GAME
    │       ├── cheats for this game, ON/OFF
    │       ├── AUTOFIRE
    │       ├── GAME SETTINGS
    │       └── MEMORY EDITOR
    └── SELECT outside a game, on a multi-slot board ── next game

Board DIP switches

SwitchON means
1Open the settings screen at every power-on
2VS mode, passed to the game as on the Japanese SNK BIOS and UniBIOS
3Mahjong panel on player 1, with its own page in INPUT TEST. Autofire is off.
4 to 6Nothing for the BIOS; some games read them
7Free play
8Freeze the game. At power-on, Sprixe BIOS says so on screen instead of staying black.

In-game menu

KeysAction
Up DownChoose a line
A or STARTOpen, or switch a cheat ON/OFF
Left RightChange a value
STARTBack

The game pauses while the menu is open and the music keeps playing.

Autofire

Open the in-game menu, go up three lines to AUTOFIRE, press A. Each of BUTTON A to BUTTON D is OFF or ON (Right turns it on), and RATE sets 15, 30 or 10 shots per second. Hold a button that is ON and it fires by itself, the first shot straight away. The setting belongs to the game and survives power-off; players 1 and 2 share it.

It works on games that read the joystick through the BIOS. Measured on player 1's A button: 89 games see it fully, 25 partly, 35 read the joystick themselves and never see it.

Settings that stay

Region, mode, cabinet settings and each game's soft-DIPs are kept in the board's backup RAM. A soft-DIP block left by another BIOS is checked before the game sees it: values out of range go back to the cartridge default.

Known limits

SMA and PVC cartridges are not recognised by the CRC page. Only the MV-2F has run Sprixe BIOS on real hardware; AES consoles and other MVS boards are untested.
