What does the Neo Geo BIOS actually do?

Put a cartridge in an MVS with no BIOS chip and nothing happens. The game does not start itself. A small program on the motherboard finds the cartridge, gets it ready and hands it control, then takes control back again and again for as long as the board is on. We know that program well, because we wrote a new one from scratch.

The first program the board runs

At power-on, the 68000 does not start in the cartridge. It starts in the system ROM, the 128 KB chip that holds the BIOS. Even a game's own program opens with an address that sends the processor back there: in the cartridge template of the NeoGeo Development Wiki, the start address is $C00402, inside the BIOS.

The original BIOS then checks the board. According to the wiki's boot process page, it writes and reads back the work RAM, the backup RAM, the palette memory and the video memory, and reports an error if one of them answers wrong. It also keeps kicking the watchdog, a timer that resets the whole board when a program stops answering. We met that one early. Without a cartridge, an early image of ours fell into a loop, and under MAME the watchdog restarted the board every 192 frames, a bit more than three seconds.

Then comes the boot screen. Ours draws it with the board's own font only, nothing taken from the cartridge's graphics.

It has to find the game

Once the board is checked, the BIOS goes looking for a cartridge. It looks at each slot in turn and reads the header at the start of the game's program. The header holds the game's NGH number, its ID, and the list of settings the game offers, with their names and choices. The BIOS shows those settings in its own menu, later on.

This is where our first image on real hardware failed. A tester burnt it for a two-slot MV-2F. The boot screen came up fine, but it always showed the same game number, E05C, with a cartridge or without one. No game started, and the board rebooted in a loop.

MAME had never shown that. At reset, the board is set up to show its own ROM in place of part of the cartridge, and on real hardware the cartridge's program does not answer until the BIOS switches that setting. Our BIOS read the header before the switch, so it read whatever was left floating on the bus. MAME serves the cartridge in both states, which is why eight images went through our test bench without a single complaint. The fix was to read the slots in the same order as the original BIOS, and the bench now imitates the floating bus.

Flash carts brought a second surprise. A NeoSD Pro and a BackBit stopped on the boot screen with an empty slot, as if they were not ready when the BIOS first looked. PrivaBIOS now scans the slots again at every frame, up to 270 times, until one answers. Under MAME, a cartridge that stays silent for 30 frames is found. On the BackBit, our tester now reports that a game starts, with an image we believe carries that change (its checksum was not recorded). On a NeoSD Pro, we still don't know: that is the first thing we are asking testers to try.

The game doesn't run on its own

A Neo Geo game is less a program that runs from start to finish than a set of jobs the BIOS asks for. The wiki's USER subroutine page lists four of them: set up the backup RAM with default high scores, show the game's own boot logo, play the demo, show the title screen. The BIOS calls the game with one of these, the game does it, and control comes back to the BIOS, which decides what happens next.

That is how the attract mode works, and why a multi-slot board can chain its games: when one demo ends, the BIOS can move on to the next cartridge and ask for its demo. On those boards, SELECT changes game, player 1 forward and player 2 back.

The four jobs are easy to name, and full of corners. kof98 ends the very first one, the backup RAM setup, with a reset of its own, so a BIOS has to live with not always getting control back. And after a game over with one credit left, the original BIOS puts the title screen back twice: we measured it under MAME on Art of Fighting. The wiki describes that second call as a probable bug, and games carry a flag to avoid it. We show the title once.

Coins, credits, and arcade or console

The coin slot is wired to the board, not to the game. The BIOS sees each coin, turns coins into credits and keeps the count in backup RAM, where the game reads it. It pulses the cabinet's mechanical coin counter after a coin, and it can lock the coin mechanisms so that the slot refuses coins. Free play is the BIOS's business too: in PrivaBIOS it is a line of the cabinet settings, and board switch 7 gives it as well.

Arcade or console is decided the same way. The BIOS tells the game whether it runs as an MVS or as an AES, and the game builds the matching version by itself. PrivaBIOS has that AES mode on MVS boards, and we measured it on Art of Fighting: player 2 is told PUSH START where the arcade version says INSERT COIN. In that mode the coin slot is locked and START alone starts a game. The region works alike, since cartridges carry data for several regions (their list of settings, for one, has a Japanese version) and the BIOS tells the game which region the board is set to.

It reads your joystick, mostly

Every frame, the BIOS reads the joysticks and the buttons and stores what it read in its RAM. Most games take their inputs from there. Some read the joystick themselves, straight from the hardware, and a few do a bit of both.

That split decides what a BIOS can add. Autofire works by making the game see a held button released part of the time, in the BIOS's copy of the inputs. A game that reads that copy sees the turbo, and a game that reads the hardware never does, whatever the BIOS. We measured player 1's A button on 164 MAME sets: 89 see the autofire fully, 25 partly and 35 never, and 15 were not measured.

Settings, scores and the test screen

The list of settings found in the cartridge header is turned into a menu by the BIOS: difficulty, lives, time limits, whatever the game declares, saved in backup RAM next to the high scores. They are called soft-DIPs, DIP switches in software. Labels are text, and text has its own traps. In the JAPAN region, Super Sidekicks' settings first came out blank on our screen: the Japanese labels use bytes outside plain ASCII, and our code wrote a space for each of them.

Because all of this lives in backup RAM, changing BIOS is the moment you could lose it. Under MAME, moving from the SNK BIOS or UniBIOS 4.0 to PrivaBIOS and back left a game's data intact, but that was one game, with no setting changed, and never on a real board. Write your settings down first.

The BIOS also owns the test screen operators use: hardware tests, colour bars and a crosshatch for the monitor, the input test, the memory card. It opens with the TEST button on the board. Our tester's MV-2F is consolized and has no TEST button at all, so PrivaBIOS also opens it with START and SELECT held at power-on.

Why people replace it

UniBIOS has been the reference for two decades. Razoola's BIOS has an in-game menu, cheats, and region and mode switching, and it has served players well. PrivaBIOS takes the same seat by another path: written from scratch, under the GPL-3.0, with its whole source open. The original BIOS was observed while it ran, under MAME, and no SNK or UniBIOS code was copied (one incident is on record). Coding agents wrote the code from those observations, and every function a player sees has a test scene under MAME, proven by planting a bug the scene must catch.

The hard part of a replacement is everything above, kept exactly as games expect it. Games are touchy about it: three games of our test matrix play out differently after half a minute to a minute when the BIOS's code merely moves, even by a single word that is never run. Under MAME, 162 of 164 sets play under PrivaBIOS, against 163 under the SNK BIOS and UniBIOS 4.0. On real hardware it has run on one board so far.

If you own an MVS and can burn a 27C1024, the latest release is on GitHub, and the testing page says what is most worth trying. A report that it works helps as much as a bug report.
