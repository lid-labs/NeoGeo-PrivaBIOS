# L'audit du 2026-10-21

Un audit en lecture seule du BIOS, confié à quatre agents la nuit du 2026-10-21 au 22 : la justesse
sur une vraie carte, l'assembleur 68000, la compatibilité et les performances, les tests et la
cohérence de la doc. **Aucun défaut critique établi.** Ce fichier dit ce qui a été relevé et ce
qu'il en est devenu ; chaque constat porte sa source dans le rapport d'origine (non versionné) et
dans le lot qui l'a traité.

## Traité par le durcissement matériel (2026-10-22)

| Constat | Ce qui a changé |
|---|---|
| Les bits SELECT de REG_STATUS_B comptés au repos par l'écran de boot et par RESUME, alors qu'ils se lisent toujours 0 sur MVS (« BIOS RAM locations ») | masqués sur MVS, comme dans `io.s` |
| Toutes les attentes de ligne exigent $1F0 exact, sans borne : un compteur de ligne autre que sous MAME figerait la machine | sept `.Lsync` identiques et les deux attentes de `c0.s` et `menu.s` bornées à ~2 trames ; éprouvé sous MAME en forçant le compteur à 0 (l'image d'avant restait figée) |
| La palette 0 jamais posée, alors que FIX_CLEAR met la tuile $020 (pleine de l'index 2, mesuré) sous elle | posée à noir par l'écran de boot et l'éditeur |
| La poignée de main $01 lue tout de suite dans `c0.s`, `dip.s`, `plantage.s` (une réponse $01 déjà là passe pour l'écho) | alignée sur `menu.s` : une trame avant de lire, une trame avant de basculer |
| REG_LSPCMODE, REG_NOSHADOW, les verrous de carte jamais posés au boot | posés aux valeurs que la référence écrit (`measured/2026-10-22-registres-au-boot.tsv`) ; les compteurs de pièces, que la référence ne pose pas, ne le sont pas |
| `plantage.s` écrivait sa sauvegarde avant de lire le cadre d'exception | cadre lu d'abord ; éprouvé pile dans la zone de sauvegarde (l'image d'avant affichait 6 à 9 valeurs fausses) |
| Le moteur de cheats écrivait d'après CH_ENTREE sans le valider | n'écrit que si CH_ENTREE est la première fiche d'un jeu de la table |
| `video.s` disait qu'INT1 n'écrit aucun registre VRAM (faux depuis MESS_OUT) ; le compte de pile de `tests.s` | commentaires corrigés |

## Ouvert

- **À mesurer avant d'y toucher** : la relecture de REG_VRAMRW après une écriture de donnée (`menu.s`,
  `tests.s`), mesurable au banc LSPC ; la portée du reset par le watchdog (le Z80, les bascules) ;
  l'initialisation du µPD4990A (commandes 8 et 7 au boot) ; CARD_ERROR qui formate sur une seule
  lecture fausse ; les états d'attente du bus.
- **Compatibilité** : le catalogue rejoué la même nuit (`measured/2026-10-22-matrice-catalogue.tsv`)
  montre que le critère « joue ET vifs non nuls » laisse passer des jeux qui ne démarrent pas de
  partie ; un diagnostic est en cours (aodk, cyberlip, ncommand, trally, alpham2, garou, sbp, dragonsh).
- **Tests** : le harnais de non-régression est écrit (`bench/non-regression.sh`, 2026-10-22) — tests
  du générateur, build, matrice des 22 contre le relevé de référence, cinq jigs contre leurs relevés ;
  éprouvé par mutation.
- **Doc** : corrigée le 2026-10-22 (lot « cohérence ») ; restent les ratios d'époque dans le corps
  de `io.s`, dont certains sont contredits par le contrat actuel — une passe sur le code.
- **Performances** : rien de notable sur le chemin courant (SYSTEM_IO ≈ 1 900 cycles en partie,
  calculé) ; `_mess_out` resauve 15 registres qu'INT1 a déjà sauvés (~260 cycles par trame) ;
  `construire.sh` écrit sous des noms fixes et deux constructions simultanées se mélangent.
